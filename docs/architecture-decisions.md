# 架构决策记录

## ADR-001：领域金额使用整数分

**状态：** 已采用。

**背景：** 现金、限价、成交额和总资产必须保持两位小数精度，JavaScript 浮点数不适合作为账本内部表示。

**决定：** 服务端领域层统一使用安全整数分；REST、WebSocket 和 UI 边界使用两位小数字符串。股票数量使用正整数。

**结果：** 撮合和结算可以直接验证资金守恒，避免浮点累计误差；边界转换需要严格拒绝格式错误、超过安全整数范围或非两位小数的输入。

## ADR-002：采用单进程模块化单体与内存状态

**状态：** 已采用。

**背景：** 本次交付强调可复现撮合、双用户演示和一键运行，不要求数据库、高可用或跨进程扩展。

**决定：** Vue 静态资源、Express REST API、WebSocket、账户账本、委托簿和撮合引擎由一个 Node.js 进程承载。模块通过应用工厂组装，测试可创建隔离实例；生产与 Docker 使用同一构建产物和启动入口。

**结果：** 部署和事务边界简单，适合教学演示与确定性测试；所有用户、订单和成交在进程重启后丢失，不能横向扩容。未来引入持久化时必须先定义事务、恢复和并发模型。

## ADR-003：权威快照配合版本化实时事件

**状态：** 已采用。

**背景：** WebSocket 可能断线、重连或产生跨连接世代的迟到消息，仅依赖增量事件无法可靠恢复状态。

**决定：** `GET /api/snapshot` 是用户状态的权威来源；WebSocket 使用版本化判别事件提升即时性。重连成功后先加载快照，期间缓冲当前连接事件，快照应用后再回放；旧连接和旧请求通过 generation 失效。

**结果：** 断线期间完成的成交能在重连后恢复，旧状态不会覆盖新状态；重连会产生额外快照请求。无效会话会停止重连并清除前端私有状态。

## ADR-004：账户创建时注入确定性种子资产

**状态：** 已采用。

**背景：** 禁止裸卖空、行情模拟器不充当交易对手，而双用户验收必须存在可出售股票。

**决定：** 每个新账户获得 `1,000,000.00` 初始现金和每支种子股票 1,000 股可用持仓。平均成本使用不可变种子基准价，不使用注册时随机波动后的实时价格。

**结果：** 双用户可以由一方卖出种子持仓、另一方用初始现金买入，测试具有确定性。种子资产不生成成交记录；注册完成后股票只通过用户交易转移。
